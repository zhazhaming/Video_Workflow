# 选题方法论

> 来源：llm.py HOTSPOT_TOPIC_SYSTEM / HOTSPOT_BRIEFING_SYSTEM、PROGRESS.md §7-9/§16（热点雷达踩坑）。

## 热点转选题的输出格式

```json
{"topics": [{
  "title": "选题标题（≤20字，可直接作为脚本输入）",
  "angle": "切入角度（20~40字，从哪个视角讲）",
  "hook": "开场钩子（≤25字，第一句台词，口语化）",
  "why": "为什么能蹭到流量（20~40字，情绪共鸣或争议点）",
  "ref": "来源热点标题"}]}
```

- 标题口语化、有钩子感，避免书面语和感叹号堆砌。
- 角度彼此不同：故事视角 / 反常识观点 / 盘点科普 / 情绪共鸣。

## 早报点评格式（帮创作者快速决定怎么拍）

每条热点给：适合形式（口播/剧情演绎/盘点/采访街采/图文快讯 ≤10字）、一句话拍摄角度（≤30字 具体可执行）、风险提示（≤20字；无写"无"）。涉时政/未证实信息 risk 必填。

## 第一波指数（burst）经验

- 新条目基础分 58、上升态势 48 起；热度权重 ×0.35，新鲜度加减；跨平台共振 +8 封顶。
- **踩坑教训：不同来源的归一化热度不能直接比较**（各源 top 恒为 100）；跨平台比较只看趋势方向与 burst。
- burst ≥70 值得追第一波；追不上第一波就做深度/反差角度。

## 数据型选题的取数纪律

- 能用公开 API 取数的先取数（行情 K 线、统计公报），日期与数值精确到源头；
- 网络被拦时换源（同源多镜像/国内替代源），**不许用编造数据补位**；
- 实时未收盘的数据标注口径（收盘/盘中）； turnout 涉"今天"的事实以实时接口为准而非昨日 K 线。
- 数据锚定后，文案只允许使用数据里出现的事实。
