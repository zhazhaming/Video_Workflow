# video-topic：内容选题

把一个想法或热点变成**可拍、合规、有流量潜力**的选题。方法论详情读 `references/topic-methodology.md`。

## 流程

1. **来源**：用户直接给题 → 跳到评估；追热点 → 用 WebSearch 搜当日热点（后端热点雷达开着时优先 `GET /api/hotspot/...`，六源聚合带第一波指数）。
2. **衍生**：每个热点衍生 1~2 个选题，角度彼此不同（故事视角 / 反常识观点 / 盘点科普 / 情绪共鸣）；不做新闻复述，必须有个人化视角或情绪张力。
3. **评估（三分钟决策）**：适合形式（口播/剧情/盘点/街采/图文 ≤10字）、拍摄角度（≤30字 具体可执行）、风险提示（涉时政/未证实必标）、第一波潜力（burst≥70 才追第一波，追不上就做深度角度）。
4. **事实底座**：选题涉及数据/年份/人名的，先取数（行情/统计源 API 或搜索），**没有可靠来源的知识点直接弃用**；数据能取到 API 的优先 API（精确、可复核）。
5. **落盘**：`backend/storage/projects/<pid>/meta.json`（id/title/topic/created_at）+ 确认目标时长（15~240s）与语气方向，交给 `video-script`。做过调研的落 `research.json`（8~10 个带出处节点，sources 逐字引用来源 URL）。

## 栏目闸门与开场数字（2026-11-13 起，硬规则）

热点是原料，不是选题。每条候选必须同时过三关，过不了直接淘汰：

1. **栏目归属**：只能归到 `ai干活` 或 `公司大赏`。归不进 → 淘汰（这就是"垂直"的机制保障）。
2. **硬过滤**：行情预测/个股/纳指 A股 涨跌、彩票、医疗诊断、明星八卦、灾难事故 → 淘汰。
3. **开场数字**：必须能说出这条视频开场要用的那个具体数字（7 纳米 / 330 块 / 68 个）。
   说不出来 → 淘汰。找不到数字的选题，注定写不出好开场。

后端已内置同一套规则（`hotspot.classify_column`），热点雷达与流水线候选会自动打标：
`column` / `opening_number` / `reject_reason`。**淘汰项在前端禁用「生成脚本」**，不要绕过。
每日热点配额：最多 2 条候选，其中至少 1 条来自 `ai干活`（`DAILY_HOTSPOT_QUOTA` / `DAILY_AI_COLUMN_QUOTA`）。

## 合规红线（硬规则）

不造谣、不煽动对立、不涉政治敏感；未证实信息一律"网传/据说"；数字必须与来源一致，**宁可如实地报 +1.08%，不可夸大"暴涨"**。
