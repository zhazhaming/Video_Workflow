# 选题方法论（video-topic skill 建成前的临时指引）

> 来源：`llm.py` HOTSPOT_TOPIC_SYSTEM / HOTSPOT_BRIEFING_SYSTEM、PROGRESS.md §7-9/§16 的热点雷达经验。
> 后续沉淀为 `video-topic` skill 后本文退役。

## 1. 选题从哪来

- **热点转化**：热点雷达（后端开着时 `GET /api/hotspot/...`）聚合抖音/头条/百度/知乎/B站/GitHub 六源，带热度归一、趋势、第一波指数（burst）。skill 流程无后端时用 WebSearch 搜当日热点。
- **自有选题**：用户直接给主题，跳到评估步骤。
- 每个热点衍生 1~2 个选题，角度彼此不同：故事视角 / 反常识观点 / 盘点科普 / 情绪共鸣。

## 2. 好选题的标准

- **不做新闻复述**，必须有个人化视角或情绪张力（共鸣点/争议点）。
- 标题口语化、有钩子感（≤20 字），避免书面语和感叹号堆砌。
- 输出四件套：标题（≤20字）、切入角度（20~40字）、开场钩子（≤25字，第一句台词）、为什么能蹭到流量（20~40字）。

## 3. 三分钟决策框架（拍不拍）

1. **适合形式**：口播 / 剧情演绎 / 盘点 / 采访街采 / 图文快讯（≤10 字定一种）。
2. **拍摄角度**：一句话、具体可执行（≤30 字），必须和热点内文强相关，不写空话。
3. **风险提示**：涉时政、未经证实信息必须标注（≤20 字）；无风险写"无"。
4. **第一波指数**：burst ≥70 的热点才值得追第一波；追不上第一波就做深度角度。

## 4. 合规红线（硬规则）

- 不造谣、不煽动对立、不涉政治敏感；**未证实信息一律用"网传""据说"表述**。
- 事实性内容（数字/年份/人名）必须有出处；找不到可靠出处的知识点直接弃用，宁缺毋滥。

## 5. 产出与落盘

选定后把选题写入 `backend/storage/projects/<pid>/meta.json`（`{"id", "title", "topic", "created_at"}`），
连同目标时长（15~240 秒，默认 60~180）与语气方向交给 `video-script`。若做了网络调研，资料整理成
`research.json`（8~10 个带出处的关键节点，年份/人名/数字必须逐字引用来源 URL，矛盾以更权威来源为准并注明分歧）。
