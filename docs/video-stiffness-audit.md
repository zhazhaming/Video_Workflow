## 0. 一句话诊断

| 层 | 问题 | 观众感受 |
|---|---|---|
| 时间轴 | 切镜、BGM 重音、数据游标、字幕四者最多差 1.4s | 「卡点不准」「数字对不上」 |
| 节奏 | 旁白轨 44%~50% 是静音；平均一镜 8.4s | 「像 PPT 在翻页」 |
| 版式 | 片名孤字、复盘卡压图、来源卡压读数、浮层压图表 | 「土」「乱」 |
| 文案 | A 股是「日期 + 点位」流水账；Mika 有 4000/5900 口误级不一致 | 「听不进去」 |

## 1. 最硬的伤：四套时钟不一致

### 1.1 实测切点 vs props 记录

按 `DataVideo` 时间轴计算的成片切点：

```
2.000 / 9.091 / 17.273 / 25.958 / 34.167 / 41.708 / 50.383
```

`renders/ashare-2026/props.json` 的 `sceneStarts`：

```
2.182 / 9.818 / 18.000 / 26.727 / 35.455 / 43.091 / 51.818
```

偏差：`0.18 / 0.73 / 0.73 / 0.77 / 1.29 / 1.38 / 1.44s`。

实测证据：`ffmpeg` 场景检测在 **34.167s** 检到第 5 镜硬切（flash），
而 props 记录第 5 镜在 35.455s；BGM 低频重音落在 **35.48s**——比画面晚 1.31s。

### 1.2 根因

- `remotion-engine/src/dv/timeline.ts:71-74` 与 `backend/app/services/voice.py:548`：
  `offset = max(2.0, snap((introFrames-15)/FPS, beats, 0.45))` → **2.000**。
- `backend/tools/build_props.py:67`：
  `offset = 下一个 >= max(2.0, raw_off) 的拍` → **2.182**。
- `build_props.py:100-111` 在**全局绝对时间**上吸附切点；
  `timeline.ts:104-115` 在**镜内相对时间**上吸附后再加 offset。
  两者选到的拍不是同一拍，误差逐镜累积。
- `qa_report.py:77-78` 直接读 `props["sceneStarts"]` 判断「落拍」，
  所以报告写 `cuts_on_beat: 6/6`，但**成片真实切点并不在拍上**（偏 0.18~0.22s）。

### 1.3 后果

- 画面切了，BGM 重音 0.7~1.4s 后才响 → 听感「拖」「软」。
- QA 绿了，人耳还是觉得不对 → 之前按报告调参，越调越偏。
- 换 BPM 时偏差会变，不是固定偏移，无法靠手动挪一轨解决。

**修法（P0）**：只保留一条时间轴。让 `build_props`/`qa_report` 调用与
`timeline.ts`/`voice.py` 同一套数学（或由 TS 侧导出 `timeline.json` 给 Python 读），
`sceneStarts` 只作为派生结果；QA 用 ffmpeg 实际帧差测切点，不再信 props。

## 2. 数据游标与解说错位（A 股片最致命）

`chart.tsx:77` 把镜内 `p` 线性映射到交易日：`D = a + floor(p * (b-a))`。
解说却是「某日 + 某值」，两者没有对齐。

| 时间 | 字幕在说 | 右上角读数 | 偏差 |
|---|---|---|---|
| 20.5s | 3月23日 单日暴跌 **3.63%** | 2026-03-31 **3892 -0.80%** | 晚 6 个交易日，且涨跌幅相反 |
| 31.0s | 5月13日 冲上全年最高 **4243** | 2026-05-29 **4069 -0.73%** | 已越过顶点 16 个交易日 |
| 44.8s | 10月30日 **3599** 年内新低 | 2026-09-30 **3842 +0.31%** | 早 30 个交易日，低点还没出现 |
| 46.6s | 11月2日 大涨 **1.08%** | 2026-10-21 **3713 -0.60%** | 反弹还没发生 |

![10月30日字幕与 9月30日读数同屏](audit/ashare-cursor-mismatch.png)

同屏还常有三套数字：字幕的 `3.63%`、浮层的 `-3.6%`、右上读数的 `-0.80%`。
观众不知道该信哪个，认知负担直接变成「生硬」。

另外 `chart.tsx:108-116` 的事件冲击波按「5 个交易日」计时，
在 sweep 镜（37 交易日/秒）里只存在 **约 4 帧**，写了等于没写；
`chart.tsx:234` 的全年参考线从第 0 帧就以 0.16 不透明度画出，**结局提前剧透**。

**修法（P0）**：
1. 给 `YearChart` 增加 `stops: {p, day}[]`（或把每句的 `start/dur` 传进 gen 场景），
   让游标「到事件日就停住」，念完再走。
2. 右上读数在事件句期间显示**事件日/事件值**，不要显示漂移中的当前值。
3. 事件爆发按「秒」而不是「交易日」计时，保证 0.5~0.8s 可见。

## 3. 节奏：一半时间是「等」

`track.wav` 实测：

| 项目 | 时长 | 有声占比 | 静音占比 | ≥0.8s 空档 |
|---|---|---|---|---|
| ashare-2026 | 62.4s | **55.5%** | **44.5%** | 16 个 |
| mika-guide-2026 | 74.1s | **50.5%** | **49.5%** | 22 个 |

空档分布极其规律：每句后 **约 1.1s**，每镜交界 **1.5~2.0s**。
原因是：

- `timeline.ts:12-16` / `voice.py:503-507`：
  `pauseAfter(0.4) + TRACK_PAUSE_BONUS(0.45) = 0.85s`，再加音频首尾静音 ≈ 1.1s；
  `TRACK_LEAD=0.9`、`TRACK_TAIL=0.6`。
- `build_props.py:78` **写死** `pause = 0.4 + TRACK_PAUSE_BONUS`，
  完全不读 `pauseAfter`，所以标点设计的停顿差异被抹平——每句都等长。
- 每镜 2~3 句、镜长 6~10.8s，平均 8.4s；mika 有 2 个 `still` 镜共 16.2s（占 22%），
  画面本身不动，只剩字幕在换。

这不是「慢」，是**等距**：句子等长、停顿等长、镜头等长，像节拍器。
真人说话不会每句都停 1.1s。

**修法（P1）**：
- `TRACK_PAUSE_BONUS` 0.45 → 0.10~0.15；`LEAD` 0.9 → 0.45；`TAIL` 0.6 → 0.4。
- `build_props` 读每句 `pauseAfter`，按标点/语义给 0.15~0.6s 的差异。
- 目标有声占比 65%~70%（同样文案约缩短 6~9s；用新增 2~3 句内容补回时长，
  或接受更紧凑的 52~55s）。

## 4. 镜头内的「死时间」

- 每镜只有一个背景 + 一个 `smoothstep` 运镜，运镜贯穿整镜；句子切换时画面没有新信息。
- mika 的关键视觉都在镜尾才出现：
  - `Scene01.tsx:43` TRENDING 在 `p=0.82`（镜内 8.25s，全片约 10.6s）才盖章，不到 2s 就切走；
  - `Scene01.tsx:40` 星标计数从 1200 爬到 5900 用了 6s；
  - `Scene07.tsx:22` 「大脑已连接」在 `p=0.82`（镜内 7.2s，全片约 44.4s）才出现；
  - `Scene06.tsx:15` 「已安装」在 `p=0.6`（镜内 4.2s）。
- 结果：前 70% 是「等它发生」，最后 1~2s 才给回报，观众早滑走了。

**修法（P1）**：
- 每个关键视觉在 `p=0.25~0.45` 完成，留 ≥3s 观看；
- 每句台词一个「微节拍」：4~8 帧的 1.5%~3% 推/回弹，或一次 2 帧的构图切换，
  让画面每 2~3s 有一次呼吸；
- `still` 镜不超过 4s；超过就拆成两个机位。

## 5. 版式硬伤（截图可查）

### 5.1 片名孤字

- ashare《一年，跌了将近8%》被折成「一年，跌了将近」/「8%」；
- mika《你敢让AI替你玩手机吗》被折成「你敢让AI替你玩手机」/「吗」。

![两条片名都出现孤字（左 A 股，右 Mika）](audit/titles-side-by-side.png)

`TitleCard.tsx:95` 只按字数选 96/118px，`display:flex; flex-wrap:wrap` 自然折行，
没有平衡断行，也没有「末行不得 1~2 字」的约束。9 字标题在 118px 下放不进 900px，
必折；折点由浏览器决定。

**修法（P0）**：按标点/拉丁词边界做 2 行平衡断行，末行 ≥3 字；按估算字宽自动降字号；
数字/百分比用 accent 色单独强调。

### 5.2 片尾复盘卡压图

`Scene07.tsx:16-27` 的 `RecapTree` 在 `p=0.6`（约 56.5s）进场；`chrome.tsx:132-143`
用 `inset:0 + justify-content:center`，直接盖在全年图上：

![片尾复盘卡与图表/坐标轴重叠](audit/ashare-recap-overlap.png)

- 复盘标题「一年，跌了将近8%」与图表曲线、4243 标注同区；
- 三列卡片压住 3599 标注和月份轴；
- footer 与字幕「这一年 你回本了吗」重复；
- 一屏同时有图表、复盘卡、字幕、水印、进度点五层。

**修法（P0）**：复盘卡进场时把图表压暗/上移或直接隐藏，用不透明底；
复盘卡占 `y=300~1200`，把 `y>1400` 留给字幕；删掉重复的标题/footer。

### 5.3 来源卡 / 速查卡 / 浮层互撞

- `Scene04.tsx:15` 的 `CiteCard` 在 `top:180; right:72`，正好压住
  `chart.tsx:346-366` 的右上读数（`top:148; right:72`）。
  ![来源卡压读数](audit/ashare-cite-overlap.png)
- `Scene05.tsx:16-24` 的 `SpeedFacts` 在 `right:72; top:560; width:430`，
  直接盖住图表右半和当前游标。
  ![速查卡压图表](audit/ashare-speedfacts-overlap.png)
- `DataVideo.tsx:185` 的 `stat/counter` 浮层固定在 `Overlays.tsx:27` 的 `top:360`，
  也压图表；s02 的 `4163`、s03 的 `-3.6%` 都与字幕/读数三数同屏。
  ![浮层压图表](audit/ashare-overlay-collision.png)

**修法（P0）**：建立「图区 / 读数区 / 字幕带 / chrome 区」四个安全区；
来源卡降级为片尾字幕或左下角小字；速查卡删除（图表已有标签）；
浮层只在图区之外出现，或直接删掉冗余的 stat/counter。

### 5.4 浅色主题没有适配

mika 是 paper 浅色底，但：

- `Subtitle.tsx:53-59` 仍是「白字 + 2.5px 黑描边 + 黑投影」；
- `DataVideo.tsx:217-225` 的镜标签仍是 `rgba(255,255,255,.92)` 白字。

在暖纸底上，白字黑边像贴纸，和整体气质断裂：

![浅色底上的白字黑边字幕](audit/mika-light-subtitle.png)

**修法（P0）**：`look.mode==="light"` 时用墨色字 + 纸色柔光/半透明底；
镜标签用 ink 色；emphasis 用 accent 下划线或色块，不用描边。

### 5.5 盖章压字幕

`Scene01.tsx:166` 的 TRENDING 章 `top:1420`，字幕块顶边约 1410，
实测全片 10.6~12.5s 直接压住「专治不想动手的你」：

![TRENDING 压字幕](audit/mika-stamp-overlap.png)

同类还有 `Scene07.tsx:151` 的「大脑已连接」`bottom:420`，离字幕带只剩 ~20px，
一旦字幕换两行就会撞。

**修法（P0）**：所有 gen 场景的「章/卡/标注」统一放在 `y≤1360`；字幕带 `y≥1400` 保留。

## 6. 文案：A 股是流水账，Mika 有事实级不一致

### 6.1 ashare-2026

现状是「日期 + 点位」的新闻播报：

```
去年10月 从3914点起步 / 年初一路涨到 4163
3月23日 单日暴跌3.63% / 半个月后 又大涨2.69%
5月13日 冲上全年最高 4243 / 很多人以为 牛市来了
```

问题：

- 对小白来说 3914/4163/4243 是抽象数字，没有「我的钱」；
- 只有时间线，没有因果（为什么跌）、没有人物、没有生活比方；
- 「阴跌」「收复失地」「过山车」是财经书面语/成语，违反 skill 的「口语、避免成语堆砌」；
- 15 句全是 2.5~3.5s、12~18 字，节奏等长。

改写方向（示例，不是终稿）：

```
去年10月，你拿10万进场
今天打开账户：9万2
中间它去过11万，也去过8万8
3月23日一天，没了3600
5月13日人人喊牛市，其实是全年顶
...
这一年，你回本了吗？
```

把「点位」翻译成「钱」，把「日期」翻译成「你的账户时刻」，再补一句「为什么」
（关税/地产/流动性任选一个，别编）。

### 6.2 mika-guide-2026

文案整体比 A 股好：有「AI 打工人/代练」的比喻、有「你刷你的 它在后台偷偷卷」的口语。
但有一处硬伤：

- 台词：「GitHub有个项目 **几天涨4000星**」
- 画面：星标计数 1200 → 5900（`Scene01.tsx:41`），kicker 也写「GitHub **5900** 星开源项目」
- 实际差 4700，不是 4000；且计数在说到「4000」时大约只到 2900。

**修法**：要么把计数起点改成 1900（1900→5900 = +4000），
要么台词改成「从1200涨到5900」。二者选一，别让画面和口播打架。

另外「AI打工人」和「游戏代练」两个比喻在相邻两句，抢同一个位置；
建议留「游戏代练」（更具体），把「打工人」让给后面的「派活」；
「账号还是你的」是信任点，值得单独一句，不要和「代练」挤在一起。

## 7. 次要但会累积的工程债

1. `voice.py:547` 仍写 `intro_frames=66`，`timeline.ts:11` 已改 48。
   当前被 `max(2.0)` 掩盖，一旦片头变长就会音画漂移；应改为共享常量/读同一份配置。
2. `build_props.py:78` 不读 `pauseAfter`（见 §3），导致「想改停顿」改不动。
3. `qa_report.py` 不测文字重叠、不测真实切点；建议增加：
   - 用帧差测切点，和 BGM 重音对齐；
   - 对字幕/卡片/图表做 bbox 重叠检测（至少关键帧）；
   - 片名孤字检测（末行字数）。
4. `motion.tsx:57-63` 有 `cameraPerLine`，但 `CameraWrap` 用整镜 `progress`，
   句间切机位时 transform 是跳变的（不是切点，是硬跳）；要么给句内 progress，
   要么明确做成 1~2 帧的 cut。
5. `chrome.tsx` 全部用绝对坐标（top/left/right），没有安全区 token；
   版式互撞是结构性的，不是某一镜没调好。

## 8. 建议的修复顺序

| 批次 | 内容 | 是否改文案/重录 | 预期 | 工作量 |
|---|---|---|---|---|
| **P0 一致性** | 单一时间轴；数据游标事件驻留；片名断行；复盘卡全屏化；删/挪互撞卡；浅色字幕；盖章让位 | 否 | 先消掉「对不上/压字/孤字」三类硬伤 | 1 天 |
| **P1 节奏** | 停顿 1.1→0.4~0.6s 且有差异；每句一个微节拍；关键视觉提前到 25~45%；still≤4s；字幕上拍 | 否（重预混+重渲） | 去掉「等」和「PPT 感」 | 1 天 |
| **P2 文案** | A 股改「一个人的 10 万」；Mika 修 4000/5900、合并比喻 | 是（重 TTS） | 去掉「听不进去」 | 0.5 天 |
| **P3 系统** | 共享 timeline.json、QA 真实切点/重叠检测、安全区 token、常量单测 | 否 | 防回归 | 1 天 |

**建议先做 P0 + P1，拿 ashare 当试点重出一版 60s 预览**：
这两批不改文案、不重录，最快能验证「生硬感」是否主要来自时间轴和节奏。
如果试点有效，再统一套到 Mika，最后再决定是否重写 A 股文案。

---

## 9. 不建议做的事

- **不要加更多粒子/故障/发光**：现在的问题是信息互相打架、时间对不上，特效只会更吵。
- **不要整体加速音频**：会破坏 TTS 语气，且不解决等距停顿。
- **不要只把镜头缩短**：旁白时长不变，缩镜会让字幕和画面更挤。
- **不要继续用 props 的 `sceneStarts` 自证卡点**：先让 QA 看真实帧。
